Das Problem

Dein Agent ist brillant. Dein Prozess ist Zufall.

Ohne Struktur ist jede AI-Session ein Unikat: mal mit Tests, mal ohne. Mal reviewed, mal direkt committet. Was gestern funktioniert hat, ist heute nicht reproduzierbar — und bei jedem neuen Feature beginnt das Aushandeln von vorn.

✕ ohne Effective Flow

Jedes Mal neu erklären

„Schreib erst einen Plan. Denk an Tests. Mach ein Review." — in jeder Session, in jedem Projekt, wieder und wieder.

✕ ohne Effective Flow

Reviews, die keiner macht

Der Agent committet, was er selbst geschrieben hat — ungeprüft. Findings landen im Chat-Verlauf und sind morgen weg.

✕ ohne Effective Flow

Zwei Harnesses, zwei Welten

Claude Code hier, Codex dort — und deine mühsam gebauten Anweisungen driften auseinander, bis nichts mehr zusammenpasst.

Der Loop

Von der Idee zum PR — mit System.

Effective Flow-Workflows sind gated: An jeder relevanten Grenze entscheidest du — oder du gibst den Rest bewusst frei und lässt ihn autonom via /goal laufen. Jede Phase hat eine messbare Abschlussbedingung und wird unabhängig verifiziert.

/effective-flow plan

Nummerierte Plan-Datei mit Workflow-Empfehlung und Statusmarker — versioniert im Repo, nicht im Chat-Verlauf.

/effective-flow build

Implementer-Agent setzt um, Test-Writer schreibt Tests, Code-Validator prüft Types, Lint und Build.

/effective-flow review

Spezialisierte Reviewer erzeugen Findings — als lokaler Report oder direkt als Issues mit Epic auf GitHub/Forgejo.

/effective-flow apply

Arbeitet Plan, Review-Report oder Issues ab — hakt das Epic Finding für Finding ab, bis nichts mehr offen ist.

Der Werkzeugkasten

15 Tools. Ein Präfix. Kein Vorladen.

Effective Flow ist ein dünner Router mit Lazy-Loading: Die Session lädt nur den Tool-Katalog — die vollständige Anweisung eines Tools erst beim Aufruf. Deine Kontext-Tokens gehören deinem Code, nicht der Tool-Doku.

Die Spezialisten

Wer implementiert, reviewt nicht.

Effective Flow delegiert an 11 spezialisierte Subagents — Implementer schreiben Code, unabhängige Reviewer prüfen ihn, der Validator hält Types, Lint und Build grün. Getrennte Rollen, getrennte Kontexte: Der Reviewer sieht den Code, nicht die Selbstgewissheit des Autors.

Jeder Agent trägt seine Konfiguration pro Harness: Modellwahl, Tool-Rechte und Sandbox-Modus sind für Claude Code und Codex getrennt definiert — aus derselben Quelldatei gebaut.

Der Name ist das Programm.

Gates statt Blindflug

Jeder Workflow hält an Freigabe-Grenzen an. Autonomie ist eine bewusste Entscheidung pro Lauf (/goal) — kein Default. Korrektur-Loops sind beschränkt und eskalieren an dich statt endlos zu drehen.

Findings überleben die Session

Reviews erzeugen persistente Artefakte: Markdown-Reports unter .effective-flow/review/ oder Issues mit Epic und abhakbarer Checkliste auf GitHub/Forgejo. Nichts versandet im Chat-Verlauf.

Parallel arbeiten, sauber liefern

Optionale Worktree-Integration: Jeder Workflow läuft in einem eigenen Git-Worktree und mündet in einen PR, lokalen Merge oder Branch — dein Arbeitsverzeichnis bleibt unberührt.

Sichere Defaults, alles opt-in

Ohne .effective-flow/config.json funktioniert alles konservativ: lokale Reports, keine Worktrees, volle Validierung. Remote-Tracker und Autonomie schaltest du gezielt frei.
