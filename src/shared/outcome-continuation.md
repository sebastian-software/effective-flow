## Outcome-bound continuation

Use this protocol within the current workflow before dependent continuation, before material
expansion, and at an outcome-directed return. It coordinates existing authority; it creates no
new tool, planning artifact, ledger, configuration, or execution sandbox.

### Primary association and checkpoint

Retain the verified repository/tracker identity, primary source reference, original outcome,
acceptance references and required safety/support boundaries. Prefer the active local plan or
existing canonical planning comment. Use the compact bilingual “Outcome checkpoint” convention
in `shared/plan-contract.md`; prose values stay in the artifact language. Preserve dated explicit
owner changes and earlier decision reasons; replace routine summaries rather than copying history.
A plan revision, child, workflow/session/repository change or new filename never silently changes
the baseline. A genuinely new owner-originated goal has a separate baseline; retain the previous
outcome's unfinished/withdrawn state. Routine approval, deep-review approval and repair approval
are neither a new goal nor an unlimited allowance.

Only the active source-owning orchestrator persists state through its existing authority:

| Existing source                                                           | State carrier                                                                                                                                                    |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local plan / canonical planning comment                                   | Update that same source under existing file/tracker mutation guards.                                                                                             |
| Sufficient plain issue without planning comment                           | Keep its requirement in the issue; include the checkpoint in the already required PR-link/failure lifecycle comment. Create no planning comment for bookkeeping. |
| Review-report fix                                                         | Reuse the implementation note already authorized on that finding.                                                                                                |
| Investigation-report fix / direct request without another writable source | Return association and checkpoint in the existing completion/handoff; do not rewrite the diagnosis or create a report for bookkeeping.                           |
| Read-only re-entry                                                        | Consume the known source/retained handoff and return a proposed delta only.                                                                                      |

For lifecycle state use only that known issue's already permitted fresh comments and retained
workflow association. Competing checkpoints mean `unknown`, never a newest-source guess. The issue
body and explicit owner clarifications remain the goal basis. A child inherits the verified parent
reference/state; workers and returning subworkflows return evidence, never competing counters.
Parallel children share one parent attempt. Source/progress-overview owners may differ: name the
source owner explicitly in the handoff. Transfer source ownership only on a non-returning handoff.
A fresh source read invalidates a stale proposal; reconcile conflicting updates through existing
expected-body/hash protections, never overwrite another owner's evidence.

Legacy metadata alone is no blocker and requires no bulk migration or corpus scan. Establish the
baseline from the already associated original requirement, acceptance and explicit owner changes.
Fresh initial work starts at `0`. Known outcome with unreconstructable prior continuation history
retains `unknown` and receives one compact reassessment before dependent continuation; a justified
bounded decision permits work without pretending the earlier history or cost was zero. Its new
boundary accounts for subsequent attempts while retaining the unknown earlier effort. Lost
handoff-only context likewise becomes `unknown`; exact counts across unrelated fresh chats without
an accessible carrier are not claimed. Missing identity/outcome blocks only dependent continuation:
name the specific missing context, never manufacture another planning workflow.

### One attempt and its evidence

An attempt is one deliberately bounded continuation toward the same original outcome after an
earlier attempt returned. Initial implementation establishes the first return checkpoint; its
internal retries are not continuations. The next two no-progress continuations record `1`, then
`2` (saturated). The outer source owner assigns one retained attempt reference before work and
evaluates it once after all returning children. Routing, worker retries, formatting fixes and
repeated read-only status queries count nothing; resumed/duplicate returns retain the reference
and consume nothing twice. If a stale/uncertain return cannot be reconciled, preserve uncertainty
instead of replaying it as a fresh attempt.
Reconstruct or correct a historical no-progress count only from verified per-attempt evidence deltas;
cumulative work summaries or still-open acceptance alone do not justify a replacement numeric count,
so return an unresolved discrepancy to the source owner.
A reconciled duplicate/resumed return with no new completed attempt or evidence leaves the entire
checkpoint byte-for-byte unchanged, including last attempt, evidence and decision; report the replay
only in the return/handoff, with no narrative or cosmetic source rewrite.

Qualifying progress is new verified evidence materially advancing a previously defined original
acceptance proof or resolving its named blocker. State which original proof advanced and how.
A necessary negative result qualifies only when it decisively answers a bounded evidence question
specified beforehand and closes uncertainty on that proof. Green model/local tests, merged child
PRs, fixtures, rewritten plans, approach-created prerequisites, renamed blockers and newly invented
subgoals do not qualify by themselves. Record the latest decisive evidence delta, cumulative
approach/investment and maintained components, remaining decisive proof and runtime/maintenance
ownership. Use observed facts and labeled estimates; missing cost is unknown. Tokens, model calls,
commits and elapsed chat time are not outcome progress or invented cost evidence.

### Trigger, judgment and finite decisions

Reassess immediately before introducing an unaccepted maintained component/service, custom
platform/library build, trust boundary, deployment target or substantial operating duty, even
when tests pass or the work is primary. Also reassess on an exhausted finite effort/attempt bound
and at the second consecutive no-progress return itself, before further optional work. Keep `2`
review-required until its decision is recorded; an existing valid remaining allowance from that
reassessment permits its next bounded attempt without repeating the same judgment.

Use the current workflow's existing judgment mechanism, never launch another workflow merely to
reassess. `effective-product` owns proportionality and the smallest coherent outcome;
`effective-delivery` owns delivery evidence/complexity judgment. Apply existing skill discovery,
central judgment handoffs and specialist relevance gates. Supply the original outcome/boundaries,
verified source, attempt/evidence delta, cumulative investment/ownership, remaining proof, current
approach, trigger, allowance and authority. Keep a compact decision, not a second full review or
repository audit. If an owner is unavailable, disclose the minimal fallback: compare the current
approach with the smallest supported alternative and an honest stop using verified evidence,
remaining proof and ownership. Label unknown alternatives unknown; sunk cost justifies nothing.

Record exactly one result in the existing source or authorized handoff:

- **Continue within authority:** give rationale, same/smaller approach, next observable original
  proof, positive finite attempt allowance and remaining attempts, stop condition, and any explicit
  owner authorization reference. An observable effort bound may supplement the attempt allowance;
  unknown time/cost is no usable bound. Resume without redundant confirmation when guarantees,
  support boundary, accepted approach and authority remain intact.
- **Owner decision required:** present the smallest consequential choice, relevant alternatives,
  cumulative investment/ownership and recommended bound in the current artifact/chat. Keep its
  endpoint blocked while independent authorized work proceeds. Ask only for changed commitments
  or missing authority; an unattended run returns a blocker and asks nothing.
- **Stop this approach:** name the reason and unfinished acceptance. Stop is neither success,
  accepted risk, waived validation, withdrawn requirement nor automatic cancellation.

Reassessment alone preserves `0`, `1`, `2` or `unknown`; it never resets history or manufactures
failures. Qualifying evidence resets the count to `0` and invalidates the old special allowance.
After a justified reassessment at saturated `2`, for example, record `allowance: 2; remaining: 2`.
Each completed attempt consumes one exactly once: an unsuccessful return retains `2` and moves
remaining `2 → 1 → 0`. With `remaining: 1` and unchanged assumptions/authority, proceed within that
decision without another review; at `remaining: 0`, restore review-required before more optional
work. Material expansion or evidence invalidating the rationale terminates the decision earlier.
Duplicate/resumed returns consume nothing twice. An unknown earlier history remains visible even
when subsequent evidence justifies a reset. Never renew an identical failed experiment/exhausted
decision without changed evidence or a specific consequential owner decision accepting the bounded
additional attempt; a routine “yes”, renamed evidence question or fresh artifact is insufficient.

### Safety, returns and recommendations

Required authorization, compatibility, accessibility, data integrity, rollback, isolation and
other original quality/safety checks remain binding. A failed required check blocks immediately,
regardless of count or remaining allowance. Existing authorized corrective work and safe
containment/restoration remain eligible; neither grants resumption of the blocked broader approach.
Narrowing supported scope requires the existing owner decision and applicable safety judgment;
checks for the retained scope are never waived to meet an effort bound.

Before return, account once, persist only through the source owner, and carry the verified primary
association, checkpoint/proposed delta, decision and unfinished original acceptance. A delivered
code milestone may be complete while its parent operational outcome remains open; report both
without reopening finished work. Preserve decomposition parsing, plan-PR continuation, archival
and lifecycle receipts. Read-only review, investigation and `next-steps` never gain primary-write
authority: report the pending source update or return the proposed delta. Apply this decision before
an outward invocation; withhold blocked continuation and any substitute plan/review/issue-creation
invocation that would evade it. Keep recommendation limits and unattended one-artifact/no-question
boundaries; use their existing `Revision required` versus operational `ABORT` distinction.
