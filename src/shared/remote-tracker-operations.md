## Remote-tracker operation reference

One row per helper operation, in the helper's own order. The call shape, dry run and `--apply`,
`cwd` and the result envelope are the remote helper contract's; this reference names only
operations and their input keys.

Keys common to every row are not repeated in it. `cwd` applies to every operation as the helper
contract states; some operations reject a missing or relative one. The `repository` and `provider`
overrides apply only to forge operations; a local row that lists `repository` reads it as its own
input. `issue` is an accepted alias of `number` on issue operations, `pullRequest` on pull-request
and review operations. A key written `payload.<key>` is read from the `payload` object when one is
present, and then flat keys beside it are ignored. Any body-carrying key may travel in the
input-file form of `remote-tracker-input-files`.

Key cells list backticked key paths separated by `, `. `` `a` or `b` `` is an alternative group,
`` `k` (if `<capability>`) `` a key required only when the probe reports that capability,
`` `x[]` (each: …; optional …) `` the keys of every element of an array, and `—` none. In Notes,
`Forgejo: unsupported` marks a static gap, `Forgejo: needs <capability>` an operation that requires
that probe capability, and `` Forgejo: `<key>` `` a key required only on Forgejo, optionally followed
by its `<type>`. A Notes cell that begins with `structured;` marks a container key whose nested
schema stays with the owner named after it: a shared fragment, or a builder function of the
helper's `remote-tracker-core.mjs`. A lenient structured builder also reads its fields flat; the
exact-key builders `follow-up-admission-build`, `issue-lifecycle-receipt-build` and
`decomposition-records-build` read them only under the container key. For a forge operation,
Result names the fields of `data.result`, or of `data` where the cell begins with `data:`; a
mutation dry run instead returns `repository`, `command` and `capability`. For a local operation,
Result names the `data` fields.

Notes that need more than a phrase:

- `issue-update-body`, `pr-update-body`, `issue-comment-update`: `expectedBodyHash` is the
  `body-hash` of the body a fresh read returned, and `expectedVersion` that read's `version`.
- `issue-list`, `pr-list`, `pr-reviews-read`: `limit` and `maxPages` bound Forgejo paging only.
- `pr-create`: a Forgejo draft (`payload.draft: true`) requires the probe capability
  `pullRequestDraftCreate`.
- `pr-mark-ready`: on Forgejo `payload.title` is the final title and must not begin with a `WIP:` or
  `[WIP]` prefix.
- `pr-acceptance-sources`: with `snapshotSessionId` and a trusted source, the read also leaves a
  private runtime snapshot, named in `snapshot`.
- `review-create`: each `line` is a positive integer, and `side` is `LEFT` or `RIGHT` (default
  `RIGHT`).
